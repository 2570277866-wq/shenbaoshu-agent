# 执行路线图

> 这份文档回答一个问题：**每一步谁做、用什么做、产出什么、交给谁。**
> 排期见 `docs/PLAN.md`，系统设计见 `docs/ARCHITECTURE.md`，硬件见 `docs/技术选型.md`。

## 一、三样东西各干什么（最容易混的地方）

| | 是什么 | 干什么 | 什么时候在场 |
|---|---|---|---|
| **Claude Code** | 开发工具（AI 编程） | 写脚本、写提示词、写文档、调试 | **只在开发时。交付后退出** |
| **Dify** | 工作流平台 | 编排节点，运行时执行流程 | 交付后企业天天用 |
| **Ollama** | 推理服务 | 跑模型，被 Dify 调用 | 交付后常驻后台 |

**一句话：Claude Code 造机器，Dify 是机器，Ollama 是发动机。**

### 由此推出的几条推论

1. **运行的时候 Claude Code 不在场。** 所以 `memory/` 由运行时 Agent 写，不由 Claude Code 写。
2. **Claude Code 只帮你做两件事：写脚本、写提示词。** 其余是你在 Dify 界面点，或 B 的活。
3. **Dify 里的一切都要能导出。** 因为 Dify 是"机器"，机器坏了得能重建 —— 配置导到 `dify/`。

## 二、三台机器

| 机器 | 配置 | 阶段一 | 交付后 |
|---|---|---|---|
| **开发机** | Mac / 独显机 | 全栈都在这 —— 开发 + 调试 + 推理 | 退出 |
| **推理机** | 待定（局域网 GPU / 云实例） | 不需要 | 跑模型 |
| **目标运行机** | 显存 1GB | 不需要 | 跑 Dify + 向量库 + 记忆服务 |

**阶段一只用开发机。** 现在开工不受任何硬件阻塞。

推理机与目标机的细节见 `docs/ARCHITECTURE.md` 1.1。

## 四、A 与 B 的分工与交接

```
A（你）                          B
│                                │
│ 工作流设计                      │ 知识库建设
│ Dify 节点编排                    │ 素材收集、脱敏
│ 提示词设计                       │ 分块、索引
│ docx 输出                        │ 检索测试
│ 触发器配置                       │
│ 记忆系统                         │
│                                │
└────────── 交接点 ◄──────────────┘
             │
    ┌────────┼────────┬──────────────┐
    ▼        ▼        ▼              ▼
 Embedding  最小     素材          检索
 型号确认   素材集   格式规范       测试结果
   ⚠最急
```

**三个交接点：**

| 交接物 | 从 → 到 | 为什么卡 |
|---|---|---|
| **Embedding 模型型号** | B → A | 不一致则检索失准，且**不报错**，极难排查。一次定死 |
| **最小素材集** | B → A | 1 类模板 + 3 类素材 + 1 类风格，够了才能出第一份样稿 |
| **素材格式规范** | A → B | 见 `knowledge/README.md`，元信息头必填 |

**A 不改知识库内容。** 这是 CLAUDE.md 的硬约束 —— 职责边界，不是能力边界。

## 五、开发节奏（每周循环）

```
周一  读 memory/lessons.md  ← 上周人工改了什么
      ↓
      判断归因
      ├─ 素材缺口 ──► 通知 B 补
      ├─ 提示词问题 ──► 改 dify/prompts/
      └─ 流程问题 ──► 改工作流 + 记 decisions.md
      ↓
周中  让 Claude Code 改 prompts/ 或 scripts/
      ↓
      重跑 python3 scripts/build_workflow.py 生成 workflow_vX.Y.yml
      ↓
      更新 docs/WORKFLOW.md 与 CLAUDE.md 第六节
      ↓
周五  跑测试项目，出样稿
      ↓
      人工审核 → 修改记录写进 memory/lessons.md
```

**每周至少跑一次真实项目。** 不跑就不知道改进有没有效。

## 六、交付后长什么样

```
企业操作员
   │  打开浏览器，填 13 项表单，上传申报指南
   ▼
目标机：Dify 工作流（CPU）
   │  检索知识库 → 抽要素 → 逐章生成 → 审查 → 转 DOCX
   ▼
推理机：Ollama（GPU）  ← 通过网络调用，代码零改动
   │
   ▼
企业下载 {project_name}_申报书_初稿.docx
   │
   ▼
人工审核（必做）→ 修改 → 提交
   │
   ▼
修改经验回写 memory/lessons.md → 下周复盘 → 改进提示词/补素材
```

**Claude Code 不在这一环里。** 交付后它是你的开发工具，不是系统组件。
