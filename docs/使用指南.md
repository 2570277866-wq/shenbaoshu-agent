# 使用指南（企业操作版）

> 面向企业操作人员。无需技术背景，按步骤操作即可。

---

## ⚠️ 先读这一段

本系统生成的是**申报书初稿**，不是可直接提交的成品。

- 系统会写：结构、行文、把您提供的素材组织成申报书语言
- 系统不会：核实数据真假、判断申报策略、替代专业审核
- 系统生成后会做**十项机械审查**（数字出处、无据佐证、格式等），
  结果在结果页列出，**block 项必须逐条处理**

**提交前必须由人逐项核对。** 特别是所有数字、资质、专利号、财务数据。
系统对没有素材的内容会标注 `【待补充：xxx】`，这些位置必须由您补全。

**未经人工审核的稿件，请勿对外提交。** 申报材料造假后果由申报单位承担。

## 一、准备工作

### 1.1 选申报对象（两类申报书）

打开首页，先看页面顶部的**「申报对象」**单选：

- **科技企业项目申报书** —— 企业申报（默认选中）
- **大学生科研项目申报书** —— 大创/学生科研项目

选哪个，下面的表单、粘贴识别、出稿章节就按哪套走。
**切换会清空已填内容**（填了一半时系统会先弹确认）。
选择会被浏览器记住，下次打开还是上次选的。

### 1.4 素材准备建议

**预期成果、项目亮点、三栏素材的写法直接决定成稿质量。**（三栏素材是
科技企业申报书专属；大学生项目没有素材栏，把相关内容写进对应表单字段即可。）建议：

- 写具体，不写空话。❌"技术领先" ✅"检测精度 99.2%，误检率低于 0.5%"
- 带数字，带对比。有基线数据的一定写上
- 有专利、软著、检测报告的，把编号一并写上
- 三栏素材**一行一条** —— 系统会给每条编 (S#) 号，正文里每个数字都必须
  挂出处，没进素材的内容系统不敢写（宁缺不编）

### 1.5 推理模型二选一（技术人员配置）

系统用两种方式之一调大模型，启动前由技术人员配好，操作人员无需关心：

| 方式 | 适用 | 配置 |
|---|---|---|
| 本地 Ollama | 有带 GPU 的机器（本机或局域网服务器），数据不出内网 | `OLLAMA_BASE_URL` + `OLLAMA_MODEL`（默认 `qwen3:14b`） |
| 云 API（DeepSeek 等） | 运行机器带不动本地模型，用云上模型代劳 | `LLM_PROVIDER=openai` + `OPENAI_API_KEY`（默认 `deepseek-chat`，可换 `deepseek-reasoner`） |

云 API 方式下运行机不需要 GPU，但**申报数据会发送到外部云上**，
「数据不出内网」的承诺不成立 —— 用于真实企业申报数据前，必须由企业
书面确认数据边界；开发演示不受此限。

## 二、操作步骤

### 步骤 1：打开系统

浏览器访问 http://127.0.0.1:8000/ （地址由技术人员提供）。

### 步骤 2：选申报对象，填表单（两种方式）

先看页面顶部「申报对象」单选（见 1.1），选「科技企业项目申报书」或
「大学生科研项目申报书」。

**方式 A：粘贴识别（推荐）。** 把项目简介、申报材料片段直接粘贴进
「粘贴识别」框，点「粘贴识别」（约 1 分钟）。系统抽成表单字段回填：

- 只识别文本里**明确提到**的，没提到就留空 —— 不会替您编
- 识别完会提示「未识别到哪些字段」，**逐项核对后再提交**，识别结果只当建议

**方式 B：手动填写。** 按 1.2 / 1.3 表格逐项填。带 **\*** 的为必填项。

### 步骤 3：提交

点「开始撰写」。**等待时间约 2–20 分钟**（取决于模型与硬件）。

页面跳到进度页，实时显示全部步骤（企业 13 步 / 学生 16 步）：

```
素材编号 → 要素抽取 → 各章生成（企业 7 章 / 学生 10 章）
→ 章节拼接 → 一致性审查
```

期间请勿关闭页面，可以最小化窗口做别的事。中断后恢复：
任务状态落盘，重新打开页面可继续看进度；服务重启会把没跑完的任务
标记为「中断」而非假装完成。

### 步骤 4：看结果，下初稿

完成后自动进结果页：

- **正文预览** —— 完整初稿
- **审查报告** —— 十项机械审查的 issues 列表，block 项必须逐条处理
- **下载 .docx** —— Word 直接打开编辑（标题黑体、正文宋体）

### 步骤 5：人工审核 ★ 必做

**这一步不能省。** 按下面的清单逐项过。

## 三、邮件下单（可选）

客户把申报需求**发邮件**到专用接单邮箱，系统自动接单、自动撰写，出稿后
通知审核员。此功能由技术人员开启（未开启时本节能跳过）。

### 3.1 客户怎么写邮件

发到接单邮箱，正文按下面 8 项写（缺项系统会回邮件要求补充，**不会开始撰写**）：

```
1. 项目名称：
2. 申报类型：（科技型中小企业 / 高新技术企业 / 专精特新 / 其他）
3. 技术方向：
4. 项目负责人：____，团队 ____ 人
5. 预算规模：
6. 预期成果：
7. 项目亮点：
8. 素材：
   企业技术参数（一行一条）
   知识产权（一行一条）
   财务数据（一行一条）
```

素材也可以放**附件**（最多 3 个、单个不超过 5MB）：.txt / .docx / .pdf。

系统收到后：

- 回执邮件列「识别到的关键信息」—— **发现识别错误请直接回复纠正**
- 识别信息不全会回邮件列出缺失项，补充后自动开始
- 出稿后系统**只把 docx 初稿发给审核员**，人工审核后再发给客户

### 3.2 审核员收什么

出稿后审核员邮箱收到一封邮件：

- 主题：【待审核】申报书初稿：《项目名》（任务号）
- 正文：任务号、客户邮箱、客户原邮件主题、审查结果（通过 / 有 warning）
- 附件：申报书 docx 初稿

任务失败（引擎报错、服务重启中断）也会通知审核员，**客户收不到失败通知**，
由审核员联系客户说明。

### 3.3 开通说明（给技术人员）

1. 新开一个专用邮箱（QQ / 163 均可），在邮箱设置里开启 IMAP/SMTP 服务，
   拿到**授权码**（不是登录密码）
2. 服务启动时设环境变量：`EMAIL_ENABLED=1`、`EMAIL_IMAP_HOST/PORT/USER/PASSWORD`、
   `EMAIL_SMTP_HOST/PORT/USER/PASSWORD`、`EMAIL_REVIEWER=审核员邮箱`
3. 起服务后日志出现「邮件接单已启用」即生效，每 2 分钟收一轮（可调）
4. 客户邮件不会被标已读（系统只读不改），方便人工复查
5. 发测试邮件验证：收到回执 → 网页任务列表出现新任务 → 出稿后审核员收到 docx

## 四、审核清单（提交前逐项核对）

### 4.1 审查报告 issues ★ 先处理这里

结果页的每条 issue 带严重级别：

| 级别 | 含义 | 处理 |
|---|---|---|
| block | 机械审查判的硬伤（数字没出处、编造数字、假出处等） | **逐条看**，改稿或补素材 |
| warn | 可疑但需人判断 | 逐条看，多数要改 |
| 待补充 | 没素材、系统明确不敢写的位置 | 必须人工补全 |

### 4.2 数字类 ★ 最高优先级

| 检查项 | 怎么查 |
|---|---|
| 财务数据 | 每个金额与财务报表核对 |
| 人员数量 | 与花名册核对 |
| 时间周期 | 与项目计划核对 |
| 技术指标 | 与检测报告、测试记录核对 |
| 专利/软著号 | 到官方系统逐个查验 |

**发现对不上的数字，一律以您的原始材料为准，直接改。** 系统可能理解偏差。

### 4.3 标注类

搜索文档中的 `【待补充】`，逐个补全。这些是系统明确表示"没素材、不敢写"的位置。

**不要直接删掉标注。** 每个标注都对应申报书的一个必填内容，删了就是空缺。

### 4.4 表述类

| 检查项 | 说明 |
|---|---|
| 绝对化表述 | "国内领先""国际先进""填补空白" —— 无佐证的删掉或改弱 |
| 与事实不符 | 系统不会核实真假，写得好听不等于真 |
| 申报策略 | 突出的重点是否符合本次申报导向 |
| 语体一致 | 全文风格是否统一 |

### 4.5 格式类

- 章节顺序是否符合申报系统要求
- 是否有遗留的 `{{ }}` 占位符
- 正文里的 (S#) 编号可对照素材核对出处（存档目录有对照表）

## 五、常见问题

**Q：生成的内容有事实错误怎么办？**
A：直接改。系统基于您提供的素材生成，素材不全会导致理解偏差。

**Q：为什么有些地方写着【待补充】？**
A：这些内容没有素材，系统按规则拒绝编造。需要您补素材重新生成，或手工补上。

**Q：为什么结果页列了一堆 issue？**
A：机械审查是安全网 —— 它只能拦「没出处、前后矛盾」这类硬伤，
拦不住语义层面的编造，所以剩余工作归人。issue 少不等于全对。

**Q：粘贴识别没识别到内容？**
A：识别只抽文本明确提到的。补一段更完整的项目介绍再试，或直接手动填。

**Q：可以生成多个申报类型吗？**
A：可以，重新选择申报类型再生成一次。不同类型的结果分别保存，不要混用。

**Q：内容不满意，能重新生成吗？**
A：可以。补充更详细的"预期成果""项目亮点"后重新生成，效果会明显改善。
**输入越具体，输出越可用。**

**Q：数据安全吗？**
A：系统本地部署，材料只在本机与内网 Ollama 推理服务之间流动，
不会上传到任何外部服务器。

**Q：可以粘贴含个人隐私的材料吗？**
A：建议先自行脱敏：身份证号、银行账号、未公开的客户名称等移除。
系统不做自动脱敏。

**Q：生成的内容能直接用吗？**
A：不能直接提交，但可以作为很好的起点。经验上人工修改量在 30% 以内即可定稿。

## 七、给操作人员的三条建议

1. **输入决定输出。** 花 30 分钟把"预期成果"和"项目亮点"写扎实，比生成后改 3 小时划算。
2. **把系统当实习生。** 它能把素材组织成申报书的样子，但不懂您的业务，也不会替您担责。
3. **每次修改都值得记录。** 您的大幅改动是我们改进系统的依据，欢迎反馈。
