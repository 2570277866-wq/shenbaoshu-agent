# 对接清单（A ↔ B）

> 合作对接就三件事：**素材、模型、规则**。
> 这份清单是给 B 看的，每次对接前过一遍。

---

## 一、总览

```
B 提供                          A 负责
────────                        ────────
素材（收集/脱敏/分块/索引）        工作流设计、Dify 编排
Embedding 模型型号 ──────────►   绑定知识库、验证检索
素材格式规范 ◄──────────────     提示词设计、docx 输出
评审要点、官方模板                触发器、记忆系统
```

**边界一句话：B 管知识库内容，A 管知识库怎么用。A 不修改知识库里的任何素材。**

## 二、时间线：什么时候要什么

按 `docs/PLAN.md` 的第 1 周排期。

| 时间 | B 要给的 | 不给会怎样 |
|---|---|---|
| **D3 前** | **Embedding 模型型号与版本** | 知识库无法开始建索引，**全线卡死** |
| **D5 前** | **最小素材集**（见 3.1） | 无法跑通单章节生成 |
| D5 前 | 申报类型确认 | 模板与知识库无法定稿 |
| 第 2 周 | 完整素材集 | 工作流调不出效果 |
| 第 3 周 | 参与检索测试 | 召回率无法验证 |

**D3 的 Embedding 型号是最急的一项。** 它卡住的不只是知识库，是整个第 1 周。

## 三、A 需要 B 提供的

### 3.1 最小素材集（第 1 周 D5 前，最关键）

跑通第一份样稿的最低要求：

| # | 类别 | 数量 | 说明 |
|---|---|---|---|
| 1 | 申报书模板 | 1 类 | 建议：科技型中小企业 |
| 2 | 企业技术素材 | ≥ 1 份 | 技术参数、检测报告 |
| 3 | 知识产权清单 | ≥ 1 份 | 专利/软著，含编号 |
| 4 | 财务数据 | ≥ 1 份 | 营收、研发投入 |
| 5 | 优秀申报书范文 | 2–3 份 | 用于风格库 |

**这五样到齐，就能出第一份样稿。**

### 3.2 Embedding 模型 ⚠ 最急

**A 定，B 对齐。** 不商量，只通知 —— 选型标准与验证方法见 `docs/技术选型.md` 第四节。

**选定：`qwen3-embedding:0.6b-fp16`**（Ollama 部署，Apache 2.0，32K 上下文，fp16 全精度）

**A 要先做完的：**

1. ✅ `ollama pull qwen3-embedding:0.6b-fp16` ← **别用 latest，latest 是 8b-q4_K_M**
2. ✅ `ollama list` 抄下 **digest** ← 关键，tag 是浮动的
3. ✅ 读插件源码确认指令前缀行为（见下）
4. ⬜ 建 20–30 题测试集，跑召回验证，≥ 90% 才算通过
5. ✅ 写入 `memory/decisions.md`

**通知 B 的字段（2026-09-18 已锁定，可直接复制）：**

```
模型：qwen3-embedding:0.6b-fp16
来源：Ollama registry
digest：67a7592a8852b7b36f6328cdec193cfb7639769f5edf344ba709b088b2a51042
维度：1024
上下文：32768
量化：fp16（未量化）
部署：Ollama，版本 0.34.0（两边一致）
指令前缀：不使用（两边一致）
```

**拉模型必须显式写全 `qwen3-embedding:0.6b-fp16`。** `latest` 指向 `8b-q4_K_M`，
是另一个模型，且 CPU 跑不动。

**两个必对齐项（不一致都会导致检索失准且不报错）：**

| 项 | 说明 |
|---|---|
| **digest** | 同 tag 不同 digest = 两个模型 |
| **指令前缀** | Qwen3-Embedding 是指令感知模型，一边加前缀一边不加，向量不在同一空间 |

| 项 | 说明 |
|---|---|
| 为什么急 | 不一致时检索失准，**且不报错** —— 症状隐蔽，排查极耗时 |
| 代价 | 确认后更换需全库重新向量化，素材越多代价越大 |
| 落地 | 写入 `memory/decisions.md`，改动走决策流程 |

**指令前缀这项已从「约定」升级为「结构性排除」**（2026-09-18 读 Dify Ollama 插件源码确认）：
`dify-official-plugins` 的 Ollama text_embedding 实现里**不存在任何前缀拼接逻辑** ——
不是「我们约定不加」，是这条路径**加不上**。

> ⚠️ 但这条保证有前提：**B 也必须用 Ollama 调同一个 digest。**
> 若 B 改用 Python 直调 `transformers` / `sentence-transformers`，前缀、池化方式、
> 归一化都可能不同 —— 保证失效，且**同样不报错**。

**一次定死。B 不必等召回验证结果再开工**：收集、脱敏、按规范分块都不依赖 embedding 模型，
只有「入库建索引」那一步才需要。digest 定了就可以并行。

### 3.3 评审相关材料

| 材料 | 用途 |
|---|---|
| 评审要点 / 打分表 | 决定模板章节结构与各章权重 |
| 官方申报模板 | 反向校准 `templates/` 的章节顺序与必填项 |
| 申报指南 | 工作流会解析它提取要求 |

**没有评审要点，模板章节就是猜的。** 这是第 2 周返工的主要来源。

### 3.4 素材规范（B 需确认接受）

细节见 `knowledge/README.md`，要点：

| 项 | 要求 |
|---|---|
| 格式 | Markdown，单文件一事，中文文件名不加空格 |
| 元信息头 | 来源 / 日期 / 适用申报类别 / 可信度，**必填** |
| 数字 | 带单位带时间点（`2024 年营收 3200 万元`），不四舍五入 |
| 脱敏 | 身份证号、银行账号、未公开客户名，**B 负责移除** |
| 无出处素材 | 标"待核实"，不得标"可信度高" |

### 3.5 分类归档

按三类分开，不混放：

```
01_模板类/    结构知识 —— 申报书长什么样
02_素材类/    事实知识 —— 这家企业什么情况  ★ 唯一事实来源
03_风格类/    表达知识 —— 申报书该怎么写
```

**混放会导致检索失准**（问"技术方案怎么写"却召回企业财务数据）。

## 七、最容易出问题的地方

| 坑 | 后果 | 规避 |
|---|---|---|
| Embedding 型号没确认就开工 | 召回差且不报错，排查数天 | 书面确认，写进 decisions.md |
| 素材格式不统一 | 分块混乱，检索噪声大 | 先给规范，B 认可后再批量交 |
| 数字带"约""左右" | 生成内容不可回溯 | 规范要求精确值，不确定的标区间 |
| 脱敏没做 | 企业隐私泄露 | 明确 B 负责，交付前抽查 |
| 素材不到位硬等 | 第 1 周全线停摆 | 先用公开范文占位，把链路跑通 |

**最后一条最重要：不要因为 B 的素材没到就停工。** 用公开范文占位，先把 ①–⑦ 步跑通，素材到了替换即可。
