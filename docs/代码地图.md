# 代码地图

项目每一份代码是干什么的、谁调谁、数据怎么流。给接手的人看的入口。

## 一、一句话架构

```
表单（申报对象二选一：企业 13 字段 / 学生 16 字段）
（inputs.json / 网页表单 / 粘贴识别 / 邮件下单（可选，只接企业单））
  │
  ▼
⓪ number_material.py    素材编号：素材三栏 → 编号单行 kb_material + kb_index（S# 对照表）
  │                        （学生 profile 无素材 → 直接空）
  ▼
① extract_elements.py   要素抽取：kb_material + 表单关键字段 → gen_elements（预算拆分/周期/团队）
  │
  ▼
各章 LLM 串行生成        build_workflow.PROFILES[profile].chapters × prompts/
  │                        （企业 7 章 prompts/02–08，学生 10 章 prompts/student/01–10）
  ▼
② assemble_document.py  章节拼接：各章拼成完整 md，整块剥掉 <think>…</think>
  │                        （章节规格来自 build_workflow.section_spec(profile)）
  ▼
③ check_consistency.py  机械审查：数字出处闭环、假出处、无据佐证、自我认证……
  │                        （学生白名单跳过企业专属 check_3 资质佐证）
  ▼
md_to_docx.py           Markdown → docx（python-docx，标题黑体 / 正文宋体）
```

## 二、一个引擎，两个入口

- **`scripts/run_pipeline.py`**（命令行）与 **`agent_service/main.py`**（网页服务）
  都只做「入口」：读输入 → 调 `run_pipeline.run_workflow(..., profile=)` →
  展示进度 / 存档（六件套，含 profile.json）。
- **`scripts/build_workflow.py` 是单一真相源**：`PROFILES` 字典（enterprise /
  student）各含章节定义、表单变量、前端分组、检查白名单、模型参数、
  提示词路径；模块级 `START_VARS` / `CHAPTERS` 等保留为**企业别名**。
  入口代码直接 import 它，不复制 —— 改章节/变量只改一处。
- 提示词在 `scripts/prompts/`，运行时直接读 —— **改提示词立即生效**，
  没有「重跑生成器」的同步步骤。

**profile 怎么贯穿全链**：前端选择 → `/api/form?profile=` 建表单 →
`/api/runs` body `{profile, fields}` → `state.json`（含 profile）→
worker 调 `run_workflow(..., profile=)` → 各节点按 profile 取章节/字段/提示词 →
存档 `profile.json`。旧任务 state.json 无 profile 键 → 前端显示回退企业。

## 三、逐文件作用

### scripts/（引擎 + 工具）

| 文件 | 作用 | 关键入口 |
|---|---|---|
| `run_pipeline.py` | 全链路串行主循环；LLM 调用封装（`LLM_PROVIDER` 切 Ollama `/api/chat` 或 OpenAI 兼容云 API `/chat/completions`）；存档六件套；CLI `--profile` | `run_workflow()`、`chat()`、`resolve_llm()`、`archive()` |
| `build_workflow.py` | 单一真相源：`PROFILES`（enterprise/student）、`get_profile()`、`section_spec()`、提示词加载、模型参数 | `user_prompt()`、`read_prompt()` |
| `number_material.py` | 节点⓪：素材逐条编号 (S1)(S2)…，压单行，产出 kb_material + kb_index | `main()` |
| `extract_elements.py` | 节点①：从素材+表单抽项目要素（预算拆分、周期、团队规模），缺项显式列 missing；`budget_subjects` 按 profile 覆盖科目表 | `main()` |
| `assemble_document.py` | 节点②：按 `in_sections`（profile 章节规格）拼接、标题降级、think 剥离、未生成章节放占位符；`SECTIONS` 仅作企业回退 | `main()` |
| `check_consistency.py` | 节点③：机械审查（数字来源标记闭环/假出处/无据佐证/自我认证等），产出 issues + block/warn 统计；`in_form_fields` / `in_checks` 按 profile 传入 | `main()` |
| `md_to_docx.py` | Markdown → docx，中文字体（标题黑体、正文宋体） | `convert()`、`save()` |
| `parse_inputs.py` | 自由文本 → 表单字段（网页「粘贴识别」用）；`profile=` 选字段/提示词/归一规则；只抽文本明说的，没提就空 | `parse_inputs()` |
| `test_*.py` ×8 | 221 项单测；`cd scripts && python3 -m unittest discover -s . -p "test_*.py"` | — |
| `prompts/` | 企业 12 个提示词（00_system + 01–09 + 10_parse_input）+ `student/` 12 个（00_system + 10 章 + parse_input），引擎唯一真相源的一部分 | — |
| `inputs.sample.json` | 样例输入（企业 13 字段），可直接喂 run_pipeline | — |

## 四、数据流里的三个关键契约

1. **素材编号 (S#)**：素材每条编号 (S1)(S2)…，`kb_index` 是 S# → 原文对照表。
   正文每个数字必须挂 (S#) 出处；kb_index 必须随稿存档，否则事后没人知道 (S3) 指什么。
2. **数字必须带出处**：十项审查里多项都卡这个 —— 表单数字用「依据申报表」标记，
   素材数字挂 (S#)，编造数字直接 block。这是「不编造」在机械层的落地。
3. **单一真相源**：章节/表单定义只存在于 `build_workflow.py`，提示词只存在于
   `scripts/prompts/` —— 别处引用不复制。

## 五、改动时的正确顺序

1. 改 `scripts/prompts/` 或 `build_workflow.py` 或节点脚本
2. 跑 `cd scripts && python3 -m unittest discover -s . -p "test_*.py"`（全绿）
3. 动了 agent_service 相关再跑 `cd agent_service && .venv/bin/python -m unittest test_service test_email_intake`
4. 更新本文档 + CLAUDE.md 第六节进度

**加第三个申报对象时的顺序**：`build_workflow.PROFILES` 加配置 → 提示词目录
`scripts/prompts/<prefix>/` → 前端自动出新选项（profiles 来自 `/api/form`）→
按各节点测试补 profile 测试。
