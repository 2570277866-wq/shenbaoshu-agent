# 产品化方案：申报书 Agent 可交付服务

> 2026-09-23 起。形态：**企业浏览器直用的 FastAPI 服务**，引擎与命令行同源。

## 一、形态

```
企业浏览器 ──► agent_service（FastAPI，目标机 1GB 显存够用）
                ├─ 表单页（13 字段，动态生成，定义出自 build_workflow.START_VARS）
                ├─ 粘贴识别（自由文本 → 表单字段，提交权在人）
                ├─ 邮件下单（可选：客户邮件 → IMAP 收信 → 解析 → 提交；
                │   必填不全回信列缺失项；出稿后 docx 邮件通知审核人）
                ├─ 任务队列：单 worker 线程，串行（Ollama 串行是事实约束）
                ├─ 进度页 / 结果页（issues 分级表 + 全文 + docx 下载）
                └─ 引擎 = scripts/run_pipeline.py（命令行同源）
推理层：LLM_PROVIDER 环境变量二选一，改配置不改代码
         → ollama：OLLAMA_BASE_URL + OLLAMA_MODEL（本机 / 局域网 GPU）
         → openai：OPENAI_BASE_URL + OPENAI_MODEL + OPENAI_API_KEY（DeepSeek 等云 API，
            数据上云，须企业书面确认）
```

链路：

```
表单 13 字段 → ⓪素材编号 → ①要素抽取 → 02–08 七章串行 LLM → ②拼接（剥 think）
→ ③十项一致性审查 → 存档五件套 + 网页查看 / docx 下载
```

## 二、接口契约

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/form` | GET | 表单字段定义（13 项，前端动态建表单，单一真相源） |
| `/api/parse` | POST | 自由文本 → 表单字段（粘贴识别）；解析失败返回 200 + error |
| `/api/runs` | POST | 提交任务 → `{run_id, url}`；422 = 校验不过 |
| `/api/runs` | GET | 任务列表（新→旧） |
| `/api/runs/{id}` | GET | 状态 + 进度事件数组 + pass/blocking |
| `/api/runs/{id}/document` | GET | 全文 Markdown（text/plain） |
| `/api/runs/{id}/report` | GET | 一致性审查报告 JSON |
| `/api/runs/{id}/docx` | GET | docx 下载（运行时转换，不落盘） |
| `/api/convert` | POST | Markdown 直传（raw text，非 JSON），回 docx 二进制；`?mode=url` 落盘返回下载链接（备选） |
| `/api/convert/{cid}/download` | GET | url 模式的下载端点 |
| `/` `/runs/{id}` `/runs/{id}/result` | GET | 页面壳（表单 / 进度 / 结果） |

任务状态机：`queued → running → done | failed`；重启后残留 running/queued
→ `interrupted`。每任务目录 `runs/<run_id>/`：`state.json` + 存档五件套。

## 三、配置（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `LLM_PROVIDER` | `ollama` | 推理层协议：`ollama` 走本机/局域网，`openai` 走 OpenAI 兼容云 API（如 DeepSeek） |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | Ollama 地址 —— 三机形态的接线点 |
| `OLLAMA_MODEL` | `qwen3:14b` | Ollama 模型名，换 32b 只改这里 |
| `OPENAI_BASE_URL` | `https://api.deepseek.com/v1` | 云 API 地址（LLM_PROVIDER=openai 时生效） |
| `OPENAI_MODEL` | `deepseek-chat` | 云模型名（deepseek-chat / deepseek-reasoner） |
| `OPENAI_API_KEY` | 无（openai 模式必填） | 云 API 密钥，只走环境变量 |
| `HOST` / `PORT` | `127.0.0.1` / `8000` | 绑定地址 |
| `AGENT_SERVICE_TOKEN` | 无 | 绑非回环地址**必须**设（启动硬校验，拒裸奔） |
| `RUNS_DIR` | `agent_service/runs/` | 任务存档目录（已 gitignore） |

邮件自动接单（全部可选，`EMAIL_ENABLED=1` 才生效；缺任一必填项则功能关闭、服务照常）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `EMAIL_ENABLED` | 无（关闭） | 必须为 `1` 才启用邮件接单 |
| `EMAIL_IMAP_HOST` / `EMAIL_IMAP_PORT` / `EMAIL_IMAP_SSL` | 无 / `993` / `1` | 收件服务器（QQ：`imap.qq.com`，163：`imap.163.com`） |
| `EMAIL_IMAP_USER` / `EMAIL_IMAP_PASSWORD` | 无 | 接单邮箱账号 / **授权码**（不是登录密码） |
| `EMAIL_MAILBOX` | `INBOX` | 收件文件夹 |
| `EMAIL_SMTP_HOST` / `EMAIL_SMTP_PORT` / `EMAIL_SMTP_SSL` | 无 / `465` / `1` | 发件服务器（QQ：`smtp.qq.com`，163：`smtp.163.com`） |
| `EMAIL_SMTP_USER` / `EMAIL_SMTP_PASSWORD` | = IMAP 的 | 不填就沿用 IMAP 账号 |
| `EMAIL_REVIEWER` | 无（启用时必填） | 内部审核员邮箱，出稿 docx 发到这里 |
| `EMAIL_POLL_INTERVAL` | `120` | 轮询秒数（收信 + 出稿巡检同一节奏） |
| `EMAIL_ACK_SUBJECT_PREFIX` | `【申报书接单】` | 回执主题前缀 |
| `EMAIL_MAX_ATTACHMENT_MB` / `EMAIL_MAX_ATTACHMENTS` | `5` / `3` | 附件大小、个数上限（.txt/.docx/.pdf） |
| `EMAIL_MAX_ATTACH_CHARS` / `EMAIL_MAX_PARSE_CHARS` | `6000` / `6000` | 单附件 / 送解析的文本字符上限 |

安全三条，别松：
1. 默认只监听 127.0.0.1；绑局域网必须设 token，否则拒绝启动
2. token 覆盖全部 `/api/*` 数据接口（`compare_digest` 比较）；页面壳不含数据
3. 推理层只连 `OLLAMA_BASE_URL` 或 `OPENAI_BASE_URL`，无其他网络请求；
   设 `EMAIL_ENABLED=1` 时**额外**连配置的 IMAP/SMTP 邮箱（邮件自动接单）。
   **用云 API（LLM_PROVIDER=openai）时申报数据会发到外部云上** ——
   「数据不出内网」承诺不成立，须先与企业书面确认数据边界

## 四、存档五件套（`output/<run_id>/` 或 `runs/<run_id>/`）

`inputs.json` / `kb_index.json` / `gen_elements.json` / `document.md` /
`check_report.json`。**kb_index 必须随稿存档** —— 没有它，事后没人能回答
「（S3）指的是什么」（scripts/README.md 素材编号契约）。

## 六、启动与验证

```bash
cd agent_service
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000
# 浏览器 http://127.0.0.1:8000/ 填表提交，约 15–20 分钟出稿

# 命令行同源引擎（真 Ollama）：
python3 scripts/run_pipeline.py scripts/inputs.sample.json
```
