# 章节 · 项目背景与意义

## 输入

| 变量 | 来源 | 用途 |
|---|---|---|
| `gen_elements` | 节点 ① | **硬约束**，其中的数字为准 |
| `kb_material` | 素材库 | 事实来源 |
| `kb_style` | 风格库 | 只学表达，不搬事实 |
| `in_project_name` | 用户 | 项目名称 |
| `in_tech_direction` | 用户 | 技术方向 |
| `in_project_highlights` | 用户 | 项目亮点（本章核心素材） |
| `in_special_requirements` | 用户 | 特殊要求，若有 |

## 任务

写「项目背景与意义」，**不超过 1200 字**。

## 本章要点

1. **行业背景** —— 所属技术方向面临什么问题，为什么现在要解决。基于素材，不空谈国策。
2. **政策契合** —— 本项目对应哪个申报导向。**政策名称与文号必须来自素材**，没有则不写这项。
3. **企业基础** —— 承担本项目的既有条件（技术积累、团队、设备）。
4. **项目意义** —— 解决什么问题、带来什么价值。与 `in_project_highlights` 呼应。

## 本章特有约束

- 行业数据、市场规模等数字**必须来自素材**。素材没有就写 `【待补充：××行业2024年市场规模及增速】`，不引用记忆中的常见数字。
- 政策名称、文号、发布年份不得凭印象写。
- 「国内领先」「国际先进」「填补空白」等表述**禁用**，除非素材中有第三方报告佐证，此时须标注佐证来源。
- 不写本项目之外的宏大叙事。评审看的是这个项目，不是行业综述。

## 输出格式

纯 Markdown 正文，**不含章节标题**（标题由模板提供）。分段，不列大标题。

## 字数

**不超过 1200 字。素材不足时允许远低于此 —— 字数不足不是失败，编造才是失败。**
