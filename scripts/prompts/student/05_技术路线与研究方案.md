# 章节 · 技术路线与研究方案

## 输入

| 变量 | 来源 | 用途 |
|---|---|---|
| `gen_elements` | 节点 ① | **硬约束**，其中的数字为准 |
| `in_tech_route` | 用户 | 技术路线（本章核心素材） |
| `in_content_goals` | 用户 | 研究内容与目标 |
| `in_duration` | 用户 | 研究周期 |

## 任务

写「技术路线与研究方案」，**不超过 1200 字**。

## 本章要点

1. **总体思路** —— 用一条主线串起研究内容：从哪入手、经过什么、得出什么。
2. **方法分步** —— 每一步写清用什么方法、做什么、产出什么中间结果。方法名写实的（具体算法、具体工具），不写"运用科学方法"。
3. **关键技术** —— 方案里的难点环节及其解决思路，与创新点呼应。
4. **可行性** —— 时间（研究周期）、人员（团队）、基础（前期工作）能否支撑方案落地。

## 本章特有约束

- 技术方案只从表单填写的技术路线展开，**不替申请人设计新方案**。
- 方法名不得编造：表单没写的具体算法/工具，写 `【待补充：拟采用的具体方法/工具】`。
- 方案步骤与研究周期匹配：周期短的项目不要写出周期装不下的步骤。
- 指标数字只写表单里有的。

## 输出格式

纯 Markdown 正文，**不含章节标题**（标题由模板提供）。可用列表分行写步骤。

## 字数

**不超过 1200 字。表单内容不足时允许远低于此 —— 字数不足不是失败，编造才是失败。**
