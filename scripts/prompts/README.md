## 章节提示词结构

每个章节提示词包含：

```
## 输入        ← 给人看的变量来源表；user_prompt 组装时摘掉
## 任务        写 <章节名>，字数 <范围>
## 本章要点
## 本章特有约束   数字必须挂 (S#) 出处、缺素材处输出 【待补充：xxx】
## 输出格式     纯 Markdown，不含章节标题（标题由拼装层提供）
```

`build_workflow.user_prompt()` 在「## 输入」位置注入**实际内容**
（表单值 / gen_elements / 本章素材 / 风格样例），不是给模型变量名。

## 编写原则

1. **约束前置。** 禁止性规则写在提示词开头，不写在结尾。模型对开头更敏感。
2. **每个章节提示词必须重复关键约束。** 不要假设模型记得 `00_system.md` —— 长上下文会稀释。
3. **给正反例。** 好例子 + 坏例子，比抽象规则有效。
4. **要素表是硬约束。** 明确写"以下数字为准，不得改动"。
5. **风格样例声明用途。** 每次注入都重申"只学表达，不搬事实"。

## 何时更新

人工修改成稿后，若同类问题重复出现 ≥ 2 次，改提示词并跑
`cd scripts && python3 -m unittest discover -s . -p "test_*.py"`。
