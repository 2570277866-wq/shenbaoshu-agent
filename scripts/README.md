Dify 代码执行节点脚本 + 本地调试脚本。

| 脚本 | 用途 | 对应节点 | 单测 | 状态 |
|---|---|---|---|---|
| `extract_elements.py` | 抽取全局要素表（人员/预算/周期/指标） | 节点 4 · 要素抽取 | 12 | ✅ |

| `chunk_document.py` | 长文档分块，控制上下文长度 | 节点 6 | 11 | ✅ |

| `call_dify.py` | 本地调用 Dify 跑工作流，调试用 | — | — | ✅ |

跑测试：

```bash
cd scripts && python3 -m unittest discover -s . -p "test_*.py"
```

**已知总览：82 项，全绿。** 改脚本后必须重跑 —— 尤其改模板时，`test_fill_template.py`

## 规范

### 通用

- 依赖：**仅标准库**，Dify 代码执行节点环境受限，不保证第三方包可用
- 编码：UTF-8，文件头 `# -*- coding: utf-8 -*-`
- 变量名：全小写，下划线分隔
- **脚本之间不互相 import** —— 每个脚本要能单独贴进 Dify 代码节点。
  少量重复（如章节切分）是有意为之，不是疏漏。

### 入口约定

Dify 按声明的输入变量名以**关键字参数**调用 `main`；本地调试传一个 dict。
两种都支持：

```python
def main(*args, **kwargs):
    inputs = _normalize_inputs(args, kwargs)
```

所以下面两种写法等价：

```python
main({"kb_material": [...]})          # 本地 / 单测
main(kb_material=[...])               # Dify 代码节点
```

### 输入输出

统一 JSON，便于节点间传递。返回字典的键必须与 `docs/ARCHITECTURE.md` 变量名逐字一致
（`gen_elements` / `gen_document` / `chk_report`），否则 Dify 里引用不到。

### 校验脚本约定

**不抛异常中断流程。** 返回结构化结果，由条件分支节点决定是否回退：

```json
{
  "pass": false,
  "issues": [
    {"type": "missing_data", "section": "经费预算", "detail": "预算明细缺失", "severity": "warn"},
    {"type": "number_mismatch", "section": "团队基础", "detail": "人员数 12 与要素表 8 不符", "severity": "block"}
  ],
  "stats": {"tbd_count": 3, "word_count": {"技术方案": 1820}}
}
```

### 契约扩展（相对 `docs/ARCHITECTURE.md` 第五节）

实现时加了两处，文档契约的超集，不影响原有字段：

| 扩展 | 位置 | 为什么 |
|---|---|---|
| `severity` 字段 | `chk_report.issues[]` | 区分阻断与降级。`pass` 只看 `block` 级 |
| `_sources` / `_budget_sources` | `gen_elements` | 每个标量的出处，节点③ 第 2 项回溯用 |
| `pass` / `stats` | `chk_report` | 条件分支节点直接读 `pass`，不用自己判 |

### 阻断与降级

`check_consistency.py` 里 `BLOCKING_TYPES` 是唯一开关，改等级改那一处，不改逻辑。

| 级别 | 判据 | 类型 |
|---|---|---|
| `block` | 续下去会产出「看似合理但错误」的结果 | 数字矛盾、杜撰资质、占位符残留、风格串事实、空稿件、检查没跑成、数字无来源标记、来源标错、数字洗白、无据佐证、模型自证 |
| `warn` | 结果明显不完整，人一眼看得出来 | 数字无出处、`【待补充】`、章节字数偏短、素材为空 |

**第 2 项「数字可回溯」是 warn 不是 block**，这条容易看着别扭，理由：正文里出现一个
素材中查不到的数字，可能是合理派生（占比、合计、年份）。一刀切成阻断会让回退循环停不下来
（重试 2 次仍不过 → 整篇作废），比漏放一个数字代价更大。放行后由人工在审核清单里兜。

**同一类问题在第 8 项是 block**，看似矛盾，实则不同：第 2 项查不出「标错来源」，
第 8 项查得出。而**标错来源的数字看上去完全合规** —— 人逐句读也看不出，只能机器拦。
第 2 项在结果上已被第 8 项包住（凡第 2 项报的，第 8 项必报且更严）；保留是因为两者的
说明不同，「素材里到处找不到」与「没标来源 / 标错来源」对定位问题各有用处。

### 素材编号契约（第 8 项的前提）

**素材必须按 `S1：…` 逐条编号**，上游节点在素材进入提示词前完成。

未编号时第 8 项**拒绝执行并报 `check_error`（block）**，不静默跳过 ——
静默跳过正是本项目反复踩的「不报错的失效」。

三类数字豁免来源标记，否则误报会淹没真报：

| 豁免 | 例 | 为什么 |
|---|---|---|
| 来自 `gen_elements` | `投入人数 8 人` | 用户表单填的，无从标 S 编号 |
| 年份 | `2024 年` | 不是指标 |
| 派生占比 | `40.0%`（= 200 / 500） | 由行内数与已知基数算出 |

> ⚠ **豁免按 `(数值, 单位)` 记账，不是只按数值。**
> 只按数值记会漏：`team_size=8` 会把正文里编造的「8 ms」一并豁免 —— v0.7 实测正是这么漏过去的。

### 安全

- 敏感信息（API Key、Token）走环境变量，**不写死在脚本里**
- 除 `call_dify.py` 调本机 Dify 外，不发起任何网络请求（数据不出内网）

## 实测发现（2026-09-18）

写脚本时踩到的、值得记下来的：

| 发现 | 影响 |
|---|---|
| 正则抽取里的「子串互吃」 | `著作权` 是 `软件著作权` 的子串，逐类型扫全文会把发明专利的数量算到软著头上。按类型名切句、类型名按长度倒序排 |
| `目标值 99.2%` 这类写法 | 比较词后常有「值/为/是/达」，正则漏了连接字就整条漏抓 |
| 表格行占位符的前缀陷阱 | `{{gen_budget_total}}` 也以 `gen_budget_` 开头，按前缀判族会把合计行当明细行展开。按**精确占位符名**判族 |
| 残留扫描要用宽松匹配 | 用同一条占位符正则去扫残留，永远扫不到 —— 格式错的本来就匹配不上。直接扫 `{{` |
