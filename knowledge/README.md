# knowledge/ — 知识库素材

Dify 知识库的原始素材。**由 B 提供并维护**，A 负责绑定与验证，不直接修改内容。

对应 `CLAUDE.md` 4.3 的 6 个知识库，按三类归档。

## 目录结构

```
knowledge/
├── 01_模板类/          结构知识 —— 申报书长什么样
│   ├── 科技型中小企业/
│   └── 高新技术企业/
├── 02_素材类/          事实知识 —— 这家企业什么情况 ★ 最关键
│   ├── 技术参数/
│   ├── 知识产权/
│   └── 财务数据/
└── 03_风格类/          表达知识 —— 申报书该怎么写
    └── 优秀申报书/
```

## 三类知识库的差异

| | 模板类 | 素材类 | 风格类 |
|---|---|---|---|
| 回答 | 长什么样 | 什么情况 | 怎么写 |
| 作用 | 章节骨架、评审要点 | **唯一事实来源** | 语体、措辞 |
| 分块 | 按章节，500–1000 字，overlap 100 | 按条目，一事一块 | 按段落 |
| 更新 | 低频（政策变化） | 高频 | 随案例积累 |
| 检索 | 按申报类型精确匹配 | 混合检索 top-k 3–5 | 按章节类型 |

**分库不混放。** 混在一起会导致"问技术方案怎么写，召回企业财务数据"。

详细方法见 `docs/ARCHITECTURE.md` 第四节。

## 文件规范

### 格式

Markdown，单文件一事，文件名用中文、不加空格。

### 元信息头（必填）

```markdown
---
来源：<文件名 / 提供方>
日期：2024-06-30
适用申报类别：科技型中小企业
可信度：高 / 中 / 低
---

正文……
```

**无出处的素材标注"待核实"，不得标为可信度"高"。**

### 数字规范

- 带单位、带时间点：`2024 年营收 3200 万元` ✅ ｜ `营收约 3000 万` ❌
- 精确值不四舍五入
- 不确定的标注区间并说明

### 脱敏（必做）

上传前移除：

- 个人身份证号、手机号、家庭住址
- 银行账号
- 未公开的客户名称、供应商名称
- 其他涉及商业秘密的内容

**系统不做自动脱敏。**

## Embedding 模型 ⚠

**A 与 B 必须使用完全相同的 Embedding 模型与版本。**

- 不一致时**不报错**，只是召回变差 —— 症状隐蔽，排查耗时
- 更换需全库重新向量化，素材越多代价越大
- 型号与版本确认后写入 `memory/decisions.md`，改动走决策流程

## 检索测试

入库后必做。方法见 `docs/ARCHITECTURE.md` 4.4。

- 测试集：20–30 条（问题 → 期望命中的条目）
- 及格线：召回率 ≥ 90%
- 不达标先修知识库，再调工作流
- 每次更新后重跑全部用例

## 素材不足时怎么办

**宁可空缺，不要填模糊表述。**

素材缺失的维度，让 Agent 输出 `【待补充：xxx】`，由企业人工补全。
填一个"约 3000 万"进申报书，比空着危险得多。
